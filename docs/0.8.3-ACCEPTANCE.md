## Large Review requests

Small requests keep the existing direct terminal submission. When a complete comparison's path list is too large, Rift uses the captured exact Git endpoints instead of enumerating every path. The starting commit is resolved to a full OID before snapshot file-list capture; advancing HEAD later cannot silently substitute that starting point. A null ending revision remains explicitly **live** working-tree/index/untracked state, not a frozen source snapshot. Fixed commit endpoints do not request unrelated worktree/untracked changes. Unresolved legacy symbolic/abbreviated endpoints are rejected before compaction with reload guidance.

If the complete instructions, selected notes and project context still exceed the 32 KiB paste transport, Rift writes the complete UTF-8 brief to a private main-owned file outside the checkout and sends a short instruction to read it. Explicit content is not silently truncated. This is an application transport fix, not an increase to a model's context window.

- Maximum complete brief: **8 MiB**.
- Per native session: **16 files / 16 MiB reserved**, including failed write attempts.
- Files are retained until the actual owning child exits; pending-write cleanup is fenced. Session quotas are not an invitation to delete arbitrary temporary files.
- Native providers may ask permission to read the file outside the checkout. Approval stays with the user; Rift does not answer trust, login or file-access prompts.
- Ordinary paste limits, one explicit delayed Enter, readiness checks, existing provider launch permissions, stale-session rejection and failed-submission draft preservation remain intact.
