# Software factory UX — design preview

Status: **interactive browser prototype, not an implemented factory runtime**. Source of requirements: [SOFTWARE-FACTORY-BRIEF.md](SOFTWARE-FACTORY-BRIEF.md). Only the standalone preview and this handoff document are owned by this UX task; no Angular/Electron integration or shared-contract change is included.

## Open

Open [`previews/software-factory.html`](previews/software-factory.html) directly in a desktop browser. It is one HTML file with embedded CSS, JavaScript and owned SVG; no build, font, image, CDN, Mermaid renderer or network dependency. Refresh resets all session state.

For a local HTTP preview, from the repository root:

```sh
python -m http.server 4187 --bind 127.0.0.1 --directory docs/previews
```

Then open `http://127.0.0.1:4187/software-factory.html`. The task-owned verification server has been stopped after capture. No other UI server is required.

## Composition and source fidelity

Primary surface: **Operate**, with secondary **Inspect**. The landing is a compact two-row Creation / Review launcher, not a hero or feature grid. Creation uses five compact workflow steps, a focused main work area, a persistent right artifact inspector and an action footer outside the scrolling content.

Reviewed source: `src/renderer/src/workspace.css`, `styles.css`, `review-workbench.css`, `app.component.html`, plus `demo.png` for layout reference only. Screenshot content was not copied. The preview inherits the native sans chrome / monospace source split, 64px top bar, 30px status bar, 5–8px radii, thin neutral dividers, charcoal surfaces and restrained lime accent. Dark tokens match the existing workspace palette. Light surfaces, ink and accent match it; muted text is slightly darkened from `#64717e` to `#606d7a` to keep small text above 4.5:1 on selected/hover backgrounds.

Review keeps Changes / Explorer on the left, code in the center and the familiar vertical Notes / Agent / Review rail on the right. Notes expands as a right drawer. Only Agent docks below the code. Review opens a full work surface; there is no Review dock and no application-level native-session follow-up composer. File navigation and checkpoint context are represented with synthetic examples, not real repository reads or a replacement implementation.

## Clickable path

1. **Creation → Requirements.** Edit the idea inline or in the requirements dialog. Saving a changed brief invalidates scope, architecture and plan approval. Sample acceptance criteria are explicitly fixed fixture content, not generated by an agent.
2. **Approve requirements → Architecture.** Inspect the decision record, owned static diagram, expandable Mermaid source and local artifact dialogs. Accept architecture separately.
3. **Plan.** Review three dependent tasks, check the scope/side-effect consent, then explicitly confirm plan r1. Starting execution is separate. Jumping ahead does not bypass prerequisites; Start is disabled before plan approval.
4. **Run.** Start the sample run. Stop, native-approval Blocked and check-Failed states are interactive. Reset sample run is an explicit fixture reset, not a native approval bypass. The completed-run fixture contains T01/T02 ready and T03 failed; its failed checks do not prevent inspection of earlier queued revisions. There are no timers, invented progress percentages or automatic approvals.
5. **Review queue.** Each T01/T02/T03 r1 has a separate patch, check receipt and supporting-artifact view. Ready and reviewed counts are independent. Marking reviewed requires confirmation and never means merged. A failed task cannot be marked reviewed. Requesting rework records feedback and a pending r2 request, leaving r1 evidence unchanged; it does not invent an executed r2.
6. **Review landing path.** Toggle Changes / Explorer, select sample files, open Notes, dock/close Agent and switch the Review rail to its full workspace. Unavailable native execution controls are disabled and labeled.

## Truth and safety boundaries

- The persistent label says **Design preview · synthetic fixture**. The status bar says browser-only, no provider/Git/filesystem operations. Sample code, transcripts, snapshot IDs and receipts are hand-authored illustrations. **None are real implementation test results.** The illustrative test patches are not runnable source.
- Production receipts need an actually executed command, cwd, source revision/digest, start/end times, exit code and retained stdout/stderr. Provider completion prose is not evidence. The preview explicitly says its fixture has no real runner, timestamps or digest.
- The artifact inspector proposes `Rift app data / factories / sample-01 / artifacts /`, outside the `reading-list/` checkout. All supporting-doc views are read-only and badged **Local · not in PR**. No artifact files are actually created. This models the isolation requirement; it does not prove filesystem isolation. Production must resolve and enforce an outside-checkout storage root, account for path/symlink boundaries and exclude these artifacts from task patches and PR staging. Ordinary untracked files or `.gitignore` alone are not the policy.
- Diagram SVG is static, authored inside the preview. No untrusted SVG, Markdown HTML or provider Mermaid is rendered. Production needs its own safe rendering/validation boundary.
- No provider calls, account reads, login, native confirmation, command execution, installation, commit, merge, deployment or schedules are connected. CSP denies connections and external resources. Approval and review state exists only in page memory.
- Immutable fixtures demonstrate revision identity and retention, not persistence, crash recovery, working-tree boundary capture or real sequential task execution. Those runtime concerns remain with the implementation/contracts work.

- Four passing desktop/theme cases: **1440×900 dark/light** and **1024×768 dark/light**.
- **60 viewport/clipping/center-hit-test gates**, including requirements and approval dialogs, Start, Stop, blocked reset, queued-review actions, docs and Review with both Notes drawer and Agent dock open.

Primary actions stay fixed outside content scroll regions. Long source lines can scroll within the code block rather than overflowing the desktop.
